## Обзор

Plexe — это агентный фреймворк для построения ML-моделей на основе описаний на естественном языке. В нём применяется
мультиагентная архитектура, в которой специализированные ИИ-агенты совместно анализируют данные, порождают решения
и строят работоспособные ML-модели в рамках автономного 6-фазного рабочего процесса.

**Точка входа:** `python -m plexe.main --train-dataset-uri <uri> --user-id <id> --intent "<task>" --spark-mode <local|databricks>`

**Docker:**
- `docker build .` — образ PySpark по умолчанию (локальное выполнение Spark)
- `docker build --target databricks .` — образ Databricks Connect (удалённое выполнение)

## Архитектура

### 6-фазный рабочий процесс (`plexe/workflow.py`)

1. **Понимание данных**: статистический анализ → определение ML-задачи → выбор метрики (с возможной генерацией пользовательской метрики)
2. **Подготовка данных**: разбиение набора данных → интеллектуальный сэмплинг (по умолчанию: 30 тыс. обучающих, 10 тыс. валидационных примеров)
3. **Базовые модели**: эвристический baseline с логикой повторных попыток
4. **Поиск модели**: управляемый гипотезами поиск по дереву на выборках (итеративное улучшение)
5. **Финальная оценка**: опциональная оценка на тесте (по умолчанию отключена, используется качество на валидации)
6. **Упаковка**: сведение артефактов в `work_dir/model/` (schemas/, config/, artifacts/, src/, evaluation/)

### Мультиагентная система (`plexe/agents/`)

Рабочим процессом управляют 14 специализированных агентов:
- **LayoutDetectionAgent** → **StatisticalAnalyserAgent** → **MLTaskAnalyserAgent** → **MetricSelectorAgent** (фаза 1)
- **MetricImplementationAgent**: генерирует код пользовательской метрики, если её нет в перечислении `StandardMetric`
- **DatasetSplitterAgent** → **SamplingAgent** (фаза 2)
- **BaselineBuilderAgent** (фаза 3)
- **HypothesiserAgent** → **PlannerAgent** → **FeatureProcessorAgent** + **ModelDefinerAgent** (цикл фазы 4)
- **InsightExtractorAgent**: анализирует результаты вариантов и наполняет `InsightStore` для будущих гипотез
- **ModelEvaluatorAgent**: многоэтапная оценка (фаза 5)

### Поиск по дереву (`plexe/search/`)

Трёхэтапная стратегия расширения дерева:
1. **Bootstrap**: создание разнообразных начальных решений с нуля (без родителя)
2. **Debug**: вероятностное исправление ошибочных листовых узлов (максимальная глубина: 2)
3. **Improve**: жадное расширение наиболее результативных решений

Каждая итерация управляется гипотезами: `HypothesiserAgent` анализирует журнал и накопленные инсайты, чтобы решить,
что попробовать дальше, `PlannerAgent` превращает это в конкретные планы (FeaturePlan + ModelPlan), а `InsightExtractorAgent`
извлекает выводы из результатов обратно в `InsightStore`, чтобы они влияли на последующие итерации.

Поиск выполняется на **выборках** (быстро), лучшее решение переобучается на **полном наборе данных** (точно).

### Интеграция рабочего процесса (`plexe/integrations/`)

Подключаемый интерфейс для связи plexe с внешней инфраструктурой:
- **`WorkflowIntegration`** (`base.py`): абстрактный базовый класс, задающий контракт (8 методов)
- **`StandaloneIntegration`** (`standalone.py`): реализация по умолчанию (локально + опционально S3)
- **`storage/`**: композируемые помощники хранения (`S3Helper`, заглушки Azure/GCS)

Пользовательские интеграции реализуют `WorkflowIntegration` и передают экземпляр в `main(integration=MyIntegration(...))`.

### Управление состоянием

- **BuildContext** (`models.py`): центральный объект состояния, передаваемый через рабочий процесс
- **SearchJournal** (`search/journal.py`): DAG всех решений, отслеживает происхождение и качество
- **InsightStore** (`search/insight_store.py`): накапливает выводы между итерациями поиска

## Команды

```bash
# Установка
poetry install

# Локальный запуск
python -m plexe.main --train-dataset-uri data.parquet --user-id user123 --intent "predict churn" --spark-mode local

# Сборка Docker-образов
make build                    # PySpark (по умолчанию)
make build-databricks         # Databricks Connect

# Запуск тестов
poetry run pytest tests/unit/
make test-integration          # Поэтапный набор интеграционных тестов pytest (seed -> search -> eval)
make test-integration-verbose  # Тот же набор с выводом логов тестов в терминал

# Форматирование и линтинг
poetry run black .
poetry run ruff check . --fix

# Быстрый интеграционный тест через Docker
make test-quick
```

## Ключевые файлы

- `plexe/workflow.py`: главный оркестратор (6 фаз)
- `plexe/main.py`: точка входа CLI
- `plexe/config.py`: dataclass конфигурации + перечисление StandardMetric + маршрутизация LLM
- `plexe/models.py`: модели данных (BuildContext, Solution, Baseline, Hypothesis, Plan)
- `plexe/helpers.py`: вычисление метрик и выбор типа модели
- `plexe/integrations/base.py`: абстрактный базовый класс WorkflowIntegration
- `plexe/integrations/standalone.py`: интеграция по умолчанию (локально + S3)
- `plexe/integrations/storage/`: абстрактные базовые классы помощников хранения и их реализации
- `plexe/search/journal.py`: отслеживание DAG решений
- `plexe/search/tree_policy.py`: стратегия поиска
- `plexe/agents/*.py`: 14 специализированных агентов
- `plexe/templates/`: шаблоны генерации кода (обучение, инференс, признаки, упаковка)
- `plexe/utils/litellm_wrapper.py`: обёртка над LLM с повторными попытками и опциональным хуком `on_llm_call`
- `plexe/utils/tooling.py`: декоратор `@agentinspectable` для функций, вызываемых агентами

## Стиль кода

- **Функции**: максимум 50 строк (не считая docstring)
- **Форматирование**: Black с длиной строки 120 символов
- **Линтинг**: Ruff с игнорированием E203/E501/E402
- **Типизация**: обязательны аннотации типов и модели Pydantic
- **Импорты**: ВСЕГДА на верхнем уровне в порядке: стандартная библиотека, сторонние, локальные; НИКОГДА внутри функций
- **__init__.py**: никакого кода реализации, кроме как в файлах `__init__.py`
- **Docstring**: обязательны для публичных API; стиль Sphinx
- **Тестирование**: пишите тесты pytest в `tests/unit/`, повторяя структуру пакета `plexe/`
- **Элегантность**: пишите максимально простое решение; избегайте переусложнения; предпочитайте удаление кода его добавлению
